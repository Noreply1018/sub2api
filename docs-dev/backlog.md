# 二开需求池

本文记录本 fork 的二次开发需求。每个需求保持简短，只写清楚目标、范围、验收和状态；复杂设计另开专题文档。

## 使用规则

- 先记录需求，再选择一个最小可交付项开发。
- 小改动可以只写一句目标；涉及网关、计费、权限、支付、数据库的改动必须补齐范围和验收。
- 完成开发和自测后，先保持 `doing` 或标记为待验收；必须经过用户验收确认后，才能把新功能状态写成 `done`。
- 提交信息中体现需求主题；状态更新为 `done` 的提交应发生在用户验收确认之后。
- 不把临时想法扩写成大段 PRD，避免 backlog 变成难维护的说明书。

## 状态说明

- `idea`：只是想法，尚未确认。
- `planned`：已确认准备做。
- `doing`：正在开发。
- `review`：开发和自测已完成，等待用户验收确认。
- `done`：已完成、已提交，并且已经用户验收确认。
- `paused`：暂缓。

## 需求模板

```md
### D000: 需求标题

- 状态：idea
- 目标：一句话说明要解决什么问题。
- 范围：涉及后端、前端、部署、文档中的哪些部分。
- 不做：明确本次不处理的内容。
- 验收：完成后如何判断可用。
```

## 待沉淀需求

### D001: 登录页增加记住我

- 状态：done
- 目标：减少自用或实验室小范围使用时反复输入账号密码的麻烦。
- 范围：前端登录页增加“记住我”选项；后端支持普通会话和长会话两种有效期。
- 不做：不关闭鉴权，不做一键免密登录，不改变现有用户权限体系。
- 验收：勾选后登录状态可保持较长时间；不勾选时仍使用默认会话时长；退出登录后会话失效。

### D002: 账号列表显示剩余额度

- 状态：done
- 目标：把账号列表的“用量窗口”改成更符合自用直觉的“剩余额度”。
- 范围：前端账号列表列名；用量进度条按剩余百分比展示。
- 不做：不改后端返回字段、统计逻辑、调度逻辑。
- 验收：账号列表显示“剩余额度”；已用率越高，显示的剩余百分比和进度条越低。

### D003: 个人模式移除余额扣费语义

- 状态：review
- 目标：让本 fork 的个人/小规模网关不再依赖用户余额，调用只依赖鉴权、分组、账号调度和用量记录。
- 范围：网关余额前置检查、usage 后置扣余额、用户侧余额/充值入口、管理侧账号和分组倍率入口。
- 不做：不删数据库字段和历史表，不迁移正式数据，不重写 usage 聚合，不把 USD 限额字段迁为 token 限额。
- 验收：余额为 0 的用户仍可使用有效 API Key 调用；请求完成后 `users.balance` 不变；`usage_logs` 继续记录 token；前端不再暴露余额、充值、账号倍率和分组倍率入口。
- 验证：2026-06-07 在 8081 开发环境设置 `RUN_MODE=personal`，将 dev 用户余额置为 0 后调用 `/responses` 返回 200，新增 `usage_logs.id=212`，`users.balance` 保持 `0.00000000`；临时耗尽 quota 的 API Key 返回 `429 API_KEY_QUOTA_EXHAUSTED`；单测覆盖 personal 下保留 RPM。
